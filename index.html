🏠 Arcalc Home Server Setup

One interactive script that turns a Linux machine into a home server: shared files, network-wide ad blocking, and a VPN for remote access. Version 0.3

Overview

The script asks before every step, explains it in plain English, and lets you say no to anything. It backs up each config file before changing it and prints a personalised guide at the end.

📁 Samba
A shared folder called HomeServer that your phone, laptop and TV can open over Wi-Fi.
🛡️ AdGuard Home
Blocks ads and trackers for every device on your network, with no app needed on each one.
🔐 WireGuard VPN
Connect securely to your home from anywhere to reach your files and keep ad blocking on mobile data.

What you need

  • A Linux machine that stays on (a spare PC, mini-PC or Raspberry Pi-class device).
  • An internet connection and a user with sudo rights.
  • Access to your router's settings (for AdGuard DNS and the VPN port forward).

How to use it

Option A – Review first (recommended)

git clone https://github.com/mahmoudelsheikh7/Setup-Server.git
cd Setup-Server
chmod +x setup_server.sh
sudo ./setup_server.sh

Option B – One command

curl -sL https://raw.githubusercontent.com/mahmoudelsheikh7/Setup-Server/main/setup_server.sh | sudo bash
Heads up: Option B runs the script without you reading it first. Only do this with code you trust.

While it runs

  • Answers in [Y/n] style: just press Enter to accept the capital-letter default.
  • Press Ctrl+C at any time to stop.
  • Forgot sudo? The script relaunches itself with it.
  • Extra options: --help and --version.

What each step does

Before the steps

Detects your package manager, checks that you can reach github.com, and asks if you are ready.

1. Samba – shared folder

  1. Installs Samba if it is missing.
  2. Asks which user may access the share, and creates ~/HomeServer for that user.
  3. Backs up /etc/samba/smb.conf, adds a [HomeServer] share, and validates it with testparm. If the config is broken, your original is restored.
  4. On Fedora with SELinux, labels the folder so Samba can use it.
  5. Starts the service (smbd on Ubuntu, smb on Fedora and Arch).
  6. Asks you to set a network password (separate from your login password; typing is hidden).
  7. Opens ports 139 and 445 in your firewall.

2. AdGuard Home – ad blocker

  1. Frees port 53 if systemd-resolved is using it (sets DNSStubListener=no) and repoints /etc/resolv.conf so the server's own DNS keeps working.
  2. Warns you if anything else still uses port 53.
  3. Opens ports 53, 80 and 3000.
  4. Downloads and runs the official AdGuard Home installer (installs to /opt/AdGuardHome). If it is already installed, this is skipped.

3. WireGuard – VPN

  1. Explains that a router port forward will be needed.
  2. If you also installed AdGuard, tells you which DNS to enter so the ad blocker works through the VPN.
  3. Downloads and runs the well-known angristan/wireguard-install script, which creates the server and a first client profile.
  4. Finds the generated .conf file and shows its location at the end.

Each step is independent: you can install any one of them alone.

After installation

Replace <SERVER_IP> with the address the script prints (for example 192.168.1.50).

📁 Open your shared folder

DeviceAddress
Linux / macOS / phonessmb://<SERVER_IP>/HomeServer
Windows\\<SERVER_IP>\HomeServer

Log in with your Samba username and the network password you chose.

🛡️ Finish AdGuard Home

  1. Open http://<SERVER_IP>:3000 and follow the setup wizard.
  2. Afterwards the dashboard is at http://<SERVER_IP> (unless you changed the port).
  3. Easiest way to protect the whole network: in your router settings, set the DNS server to <SERVER_IP>.
  4. Advanced: let AdGuard hand out IP addresses (DHCP) instead. Turn off the router's DHCP first, and never run two DHCP servers on one network.

🔐 Use the VPN

  1. Import the generated .conf file (or scan its QR code) in the WireGuard app on your phone.
  2. Required: in your router, forward the UDP port you chose during setup to <SERVER_IP>. The script shows the port at the end.
  3. To add more devices later, run the script again and choose WireGuard.
Give the server a fixed IP. Create a "DHCP reservation" for it in your router. If its address changes, the share, DNS and VPN forward will all stop working.

Ports the script opens

PortServicePurpose
139/tcp, 445/tcpSambaFile sharing
53/tcp, 53/udpAdGuard HomeDNS (ad blocking)
3000/tcpAdGuard HomeFirst-time setup wizard
80/tcpAdGuard HomeDashboard
UDP (your choice)WireGuardVPN, must be forwarded on the router

The script supports ufw and firewalld. If ufw is installed but switched off, the rules are saved and apply if you enable it later. If no firewall is found, nothing needs opening.

Security: never forward ports 53, 80, 139, 445 or 3000 on your router to the internet. Only the WireGuard UDP port should be forwarded.

Files it changes, and backups

FileWhy
/etc/samba/smb.confAdds the [HomeServer] share

/etc/resolv.confKeeps the server's own DNS working

Backups are saved next to the original as <file>.bak.YYYYMMDD-HHMMSS. To undo a change:

sudo cp /etc/samba/smb.conf.bak.YYYYMMDD-HHMMSS /etc/samba/smb.conf
sudo systemctl restart smbd    # "smb" on Fedora / Arch

To remove AdGuard Home:

sudo /opt/AdGuardHome/AdGuardHome -s uninstall

Troubleshooting

I can't open the shared folder

Check the service is running (systemctl status smbd, or smb on Fedora/Arch), that you used the right server IP, and that you log in with the Samba password, not your login password. Reset it with sudo smbpasswd -a YOUR_USER.

The script says port 53 is still in use

See what is using it: sudo ss -lntup | grep ':53 '. Common culprits are dnsmasq or another DNS server. Stop or disable it, then run the script again.

The server lost internet after the AdGuard step

Restore the backup of /etc/resolv.conf (or resolved.conf) from the .bak files, then restart systemd-resolved. Also finish the AdGuard setup wizard: until it is done, nothing answers DNS on this machine.

Devices are not getting ad blocking

Make sure your router's DNS is set to the server IP, and reconnect the device to Wi-Fi so it picks up the change. Some phones use "Private DNS" or a browser's built-in secure DNS, which bypasses AdGuard.

The VPN connects but nothing loads, or it will not connect

Check that the chosen UDP port is forwarded to the server. If your provider uses CGNAT (you do not have a public IP), port forwarding cannot work; ask the provider for a public IP. If you use a dynamic IP, a dynamic DNS name helps.

Something failed and I want to see what happened

Read the log: sudo less /var/log/setup-server.log.

FAQ

Is it safe to run the script twice?

Yes. It will not add a second [HomeServer] share, and it skips AdGuard Home if it is already installed. Each run makes new timestamped backups.

Do I have to install everything?

No. Each of the three steps asks separately.

Does it enable my firewall?

No. It only adds rules. It never switches a firewall on or off, so it cannot lock you out of SSH.

Where do the AdGuard and WireGuard installers come from?

AdGuard Home uses AdGuard's official install script. WireGuard uses the open-source angristan/wireguard-install script. Both are downloaded from GitHub at run time.

Can I change the shared folder location?

By default it is ~/HomeServer. To use another path, edit the path = line of the [HomeServer] section in /etc/samba/smb.conf and restart Samba.
